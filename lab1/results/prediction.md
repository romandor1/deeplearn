# Прогноз до досліду з навмисною помилкою

Складено до запуску `main.py --bug`. Помилка: у градієнті за логітами прибрано ділення на N = 105,
тобто dZ2 = P − Y замість dZ2 = (P − Y) / N. Прямий прохід, функція втрат, еталон PyTorch,
формула чисельної похідної, початкові параметри та 105 об'єктів — без змін; ваги не оновлюються.

1. **Чи зміниться втрата.** Ні. Втрата обчислюється прямим проходом, який не змінювався.
   L(NumPy) = L(PyTorch) ≈ 1.456200780114282; рядок «Втрата» у звірці з PyTorch має пройти.
2. **Як зміняться ненульові градієнти.** Усі чотири градієнти (W1, b1, W2, b2) лінійно залежать від dZ2,
   а маска ReLU та W2 від помилки не залежать. Отже, кожен ненульовий елемент зросте рівно в N = 105 разів;
   нульові елементи (якщо є) залишаться нульовими. Напрямок градієнта не зміниться, зміниться лише масштаб.
3. **Які перевірки виявлять помилку.**
   - звірка втрати з PyTorch — не виявить (втрата правильна);
   - звірка градієнтів з PyTorch — виявить для всіх чотирьох градієнтів (різниця ≫ 1e-12);
   - чисельна перевірка — виявить для всіх чотирьох параметрів: похідна правильної функції втрат
     збігається зі справжнім градієнтом, а backward() дає у 105 разів більше (різниця ≫ 1e-7).
